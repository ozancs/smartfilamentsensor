===============================================================================
  SMART FILAMENT SENSOR (SFS) — Klipper Integration Guide v3.1.2
===============================================================================

  ESP32 + AS5600 encoder based filament sensor with native Klipper module.
  ESP32 only measures filament movement. All underextrusion detection
  and pause logic runs inside Klipper.

  v3 CHANGE: clog decisions are averaged over DISTANCE (mm of commanded
  extrusion), not over seconds. The sensor is frame-mounted and reaches the
  toolhead through a bowden tube, so toolhead motion drags filament back and
  forth through the encoder -- single reads swing from -13.8mm to +17.2mm
  against a 7mm command. That drag averages out over distance; a clog does
  not. See "DETECTION TUNING" below.


===============================================================================
  1. INSTALLATION
===============================================================================

  Option A — Git install (recommended, enables auto-update):

    cd ~
    git clone https://github.com/ozancs/smartfilamentsensor.git
    ~/smartfilamentsensor/install.sh

  Add to moonraker.conf for automatic updates:

    [update_manager smart_filament_sensor]
    type: git_repo
    path: ~/smartfilamentsensor
    origin: https://github.com/ozancs/smartfilamentsensor.git
    install_script: install.sh
    primary_branch: main
    managed_services: klipper

  Option B — Manual install:

    1. Upload smart_filament_sensor.py via Mainsail/Fluidd (Machine tab)
    2. SSH: mv ~/printer_data/config/smart_filament_sensor.py ~/klipper/klippy/extras/

       mv, not cp. A leftover copy in the config folder appears in the
       Mainsail/Fluidd file list as though it were a config file, and
       editing that copy does nothing -- Klipper loads klippy/extras/.

  Then add to printer.cfg:

    [smart_filament_sensor sfs]
    serial: auto                    # fixed by-id path strongly recommended
    baud: 115200
    detection_length: 7.0           # mm of extrusion per encoder read
    detection_window: 200.0         # mm of extrusion averaged per decision
    underextrusion_max_rate: 0.5    # deficit that counts as a clog
    min_window_samples: 8           # reads required before deciding
    encoder_scale: 1.0              # encoder mm multiplier (bias correction)
    gain_tolerance: 0.25            # |gain-1| above this disarms detection
    pause_on_runout: True
    runout_gcode: PAUSE
    health_check_interval: 30.0

  UPGRADING FROM v2.x:
    underextrusion_period is no longer the averaging window. Replace it with
    detection_window (millimetres). Old configs still load -- the value is
    reused as a sample-staleness timeout -- but it no longer does what its
    name says.

  Step 4 — Restart Klipper:

    sudo systemctl restart klipper


===============================================================================
  2. CONFIG PARAMETERS
===============================================================================

  serial                 ESP32 serial port. "auto" = auto-detect via
                         PING/PONG handshake (recommended). Or use a
                         stable path like /dev/serial/by-id/...
  baud                   Baud rate, must match ESP32 firmware (default: 115200)
  detection_length       mm of extrusion between each check (default: 7.0)
  pause_on_runout        automatically pause on detection (default: True)
  runout_gcode           gcode to run on clog/runout (default: PAUSE)
  underextrusion_max_rate  underextrusion ratio threshold (0.0-1.0).
                         0.5 = pause if actual extrusion < 50% of expected.
                         (default: 0.5)
  underextrusion_period  how many seconds underextrusion must persist
                         before triggering a pause (default: 5.0)
  health_check_interval  seconds between magnet health checks (default: 30.0)

  How detection works:
    - Klipper extrudes 7mm, ESP32 encoder measures actual movement
    - Rolling underextrusion rate is calculated over recent readings
    - If rate exceeds underextrusion_max_rate, a timer starts
    - If it stays bad for underextrusion_period seconds -> PAUSE
    - If it recovers before the timer expires -> timer resets, no pause
    - Single bad readings are NEVER enough to pause a print


===============================================================================
  3. GCODE COMMANDS
===============================================================================

  -- Clog Detection --

  SFS_STATUS
      Show current sensor state: connection, magnet health,
      underextrusion rate, timer status, detection config.

  SFS_ENABLE
      Enable clog detection. Resets odometer and re-syncs extruder.

  SFS_DISABLE
      Disable clog detection without disconnecting the sensor.

  SFS_RESET
      Re-sync Klipper extruder position with ESP32 odometer.
      Clears underextrusion history and resets timer.

  -- Calibration --

  SFS_AUTO_CALIBRATE [TEMP=240] [LENGTH=50] [SPEED=100]
      One-command calibration. Heats hotend to TEMP, extrudes
      LENGTH mm at SPEED (mm/min), auto-saves result.
      No manual steps needed — just run and wait.

      TEMP    Hotend temperature in C (default: 200)
      LENGTH  Filament to extrude in mm (default: 50)
      SPEED   Extrusion speed in mm/min (default: 100)

  SFS_CALIBRATE [LENGTH=10]
      Manual calibration start. You control the extrusion.
      After filament stops, waits 5s then auto-saves.

  SFS_CALIBRATE_APPLY
      Force-save calibration immediately (skip 5s wait).

  SFS_CALIBRATE_STOP
      Cancel active calibration without saving.

  -- ESP32 Settings --

  SFS_SET [SENS=<1-50>] [NOISE=<1-20>] [BRIGHT=<1-255>] [DIR=<1/-1>] [CAL=<float>]

      SENS    Movement sensitivity (encoder steps). Higher = less sensitive.
      NOISE   Noise filter deadband. Higher = more filtering.
      BRIGHT  Status LED brightness.
      DIR     Encoder direction. Set -1 if sensor reads backwards.
      CAL     Calibration factor (deg/mm). Normally set by SFS_CALIBRATE.

  Examples:
      SFS_SET BRIGHT=10
      SFS_SET SENS=3 NOISE=2
      SFS_SET BRIGHT=80 DIR=-1


===============================================================================
  4. CALIBRATION WALKTHROUGH
===============================================================================

  Automatic (recommended):

    SFS_AUTO_CALIBRATE TEMP=240 LENGTH=50 SPEED=100

    That's it! The sensor heats the hotend, extrudes 50mm, and saves.

  Manual (if you need more control):

    1.  SFS_CALIBRATE LENGTH=50       ; start calibration
    2.  G1 E50 F100                   ; extrude 50mm slowly
    3.  ; Wait 5 seconds...           ; ESP32 auto-saves
        ; or: SFS_CALIBRATE_APPLY     ; save immediately

  Output:
    >>> CALIBRATION SUCCESS!
    >>> Measured: 49.82 mm | Target: 50.0 mm
    >>> New Cal Factor: 12.3456 deg/mm (saved)

  If the result is unusual (< 3 or > 50 deg/mm), a warning appears.
  Check magnet position, encoder direction, or re-calibrate.

  Tips:
    - Longer calibration (50-100mm) = better accuracy
    - Extrude slowly (F60-F100) for consistent results
    - Cal factor is saved to ESP32 flash, survives power off


===============================================================================
  5. OPTIONAL PAUSE / RESUME MACROS
===============================================================================

  Note: Mainsail.cfg already includes PAUSE/RESUME macros.
  Only add these if you DON'T have them:

    [gcode_macro PAUSE]
    rename_existing: BASE_PAUSE
    gcode:
      SAVE_GCODE_STATE NAME=PAUSE_state
      BASE_PAUSE
      G91
      G1 Z10 F600
      G90
      G1 X10 Y10 F6000

    [gcode_macro RESUME]
    rename_existing: BASE_RESUME
    gcode:
      RESTORE_GCODE_STATE NAME=PAUSE_state MOVE=1 MOVE_SPEED=80
      BASE_RESUME


===============================================================================
  6. ADVANCED FEATURES (v2.5)
===============================================================================

  -- Time-Based Underextrusion Detection --

  Instead of pausing on every single bad reading, the module uses
  a time-based approach (inspired by Roadrunner filament sensor):

    1. Rolling underextrusion rate is calculated from recent readings
    2. If rate > underextrusion_max_rate -> timer starts
    3. If rate stays bad for underextrusion_period seconds -> PAUSE
    4. If rate recovers -> timer resets, print continues

  This means:
    - A momentary hiccup never pauses your print
    - A real clog is detected within seconds
    - Gradual nozzle clogs are caught by sustained underextrusion

  SFS_STATUS shows the timer:
    underextrusion_timer=idle      -> all good
    underextrusion_timer=2.3s      -> alarm active, counting

  -- Auto-Detect Serial Port --

  Set serial: auto in printer.cfg. The module will:
    1. Scan /dev/serial/by-id/ for ESP32 devices
    2. Send PING and verify PONG response
    3. Fall back to /dev/ttyACM* and /dev/ttyUSB* with verification
  This prevents grabbing CAN adapters or EBB boards by mistake.

  -- Retraction Filter --

  Retraction moves (negative E) are properly handled:
    - Normal retraction (up to 20mm): tracked but not reset
    - G92 E0 or slicer E-reset (>20mm jump): encoder re-synced
  Retract + unretract cancel out in the encoder, no false triggers.

  -- Magnet Health Monitoring --

  Every health_check_interval seconds, the ESP32's magnet is checked:
    ok          Magnet detected, AGC in healthy range
    too_weak    Magnet signal weak (move closer)
    no_magnet   No magnet detected (critical)

  -- Sensor Connection Watchdog --

  If no response is received within health_check_interval + 10s,
  the sensor is marked disconnected. All commands check connection
  before executing — no silent failures.

  If the serial reader thread crashes, it's detected and reported.

  -- Homing Awareness --

  Detection is paused during homing moves. Odometer re-syncs after.

  -- Moonraker / Dashboard Data --

  get_status() exposes:
    enabled               bool    detection on/off
    sensor_connected      bool    ESP32 communication status
    magnet_state          string  ok / too_weak / no_magnet
    magnet_agc            int     raw AGC value (0-255)
    underextrusion_rate   float   0.0 (perfect) to 1.0 (total clog)
    underextrusion_max_rate float configured threshold
    underextrusion_alarming bool  timer is running
    detection_length      float   mm between checks
    is_printing           bool    print state
    is_homing             bool    homing in progress


===============================================================================
  7. TROUBLESHOOTING
===============================================================================

  "Sensor not found" / auto-detect failed
    - Check ESP32 is connected: ls /dev/ttyACM* /dev/ttyUSB*
    - Make sure no other process holds the port (screen, minicom)
    - Add user to dialout: sudo usermod -aG dialout $USER
    - Try setting serial to explicit path instead of auto

  "Sensor disconnected" warning
    - Check USB cable
    - Try a different USB port (avoid hubs)
    - Run FIRMWARE_RESTART to reconnect

  "Magnet not detected"
    - Check magnet is centered in the holder
    - Verify AS5600 air gap is 1-2mm
    - Check AGC in SFS_STATUS (healthy: 40-200)

  False pauses / too sensitive
    - Increase underextrusion_max_rate (e.g. 0.7 = only pause if <30% flow)
    - Increase underextrusion_period (e.g. 10.0 = must persist 10 seconds)
    - Re-calibrate: SFS_CALIBRATE LENGTH=100

  Never detects clogs
    - Decrease underextrusion_max_rate (e.g. 0.3)
    - Decrease underextrusion_period (e.g. 3.0)
    - Check SFS_STATUS — is detection enabled?
    - Verify sensor is connected and magnet OK

  Encoder reads wrong direction
    - SFS_SET DIR=-1

  "ERROR - sensor not connected" on commands
    - Sensor is offline, commands are blocked for safety
    - Plug in sensor and run FIRMWARE_RESTART

===============================================================================
  DETECTION TUNING
===============================================================================

  detection_window (mm of commanded extrusion averaged per decision)

    Bowden drag is bounded in millimetres, so its relative contribution
    shrinks as the window grows. A clog reads ~100% deficit at any window
    size. Worst false reading produced by drag alone, measured on real logs:

        25 mm  -> 260 %        150 mm ->  58 %
        50 mm  -> 106 %        200 mm ->  41 %   <- default
       100 mm  ->  88 %        300 mm ->  26 %

    Larger  = safer against false pauses, slower to catch a real clog.
    Smaller = faster reaction, less margin.
    At 200mm a total clog trips after ~115mm of extrusion (~25s typical).

    If your sensor sits very close to the extruder with little tube between
    them, drag is smaller and you can lower this. If you still see false
    pauses, raise it before touching underextrusion_max_rate.

  min_window_samples

    Floor on how many reads must be in the window regardless of distance.
    Stops a decision being made from two or three readings.

  encoder_scale

    Multiplies every encoder reading. Only for a steady bias you have
    measured and cannot remove by calibrating the ESP32. Prefer fixing the
    calibration; this is an escape hatch, not a substitute.

  gain_tolerance

    The module continuously measures the long-run ratio of measured to
    commanded extrusion (SFS_STATUS -> encoder_gain). If |gain - 1| exceeds
    this, clog detection DISARMS and prints a warning instead of pausing.
    A steady gain error is indistinguishable from a partial clog inside a
    single window, so the module refuses to guess.

===============================================================================
  DIAGNOSING A LOW encoder_gain
===============================================================================

  Run SFS_STATUS after a print. encoder_gain should be near 1.000.

  If it is low (encoder reads less than the extruder commanded):

  0. Is encoder_gain NEGATIVE? The encoder is counting backwards -- flip it
     with SFS_SET DIR=-1 (or DIR=1), then SFS_RESET. This happens if the
     magnet or its holder is reinstalled the other way up. Calibration is
     unaffected: the firmware takes the absolute value, so only the sign is
     wrong.

  1. SFS_DIAG -- check the register dump.

     zpos / mpos / mang non-zero
         The ANGLE register is being scaled and clipped by the chip. The
         firmware uses rawAngle() so this no longer matters, but it means
         someone wrote those registers.

     agc at 0, or at the top of its range
         Magnet too strong / too weak. Ideal AGC is the MIDDLE of the range:
         ~64 at 3.3V (range 0-128), ~128 at 5V (range 0-255). Adjust the air
         gap to 1-2mm. Both extremes degrade angle accuracy.

  2. SFS_AUTO_CALIBRATE TEMP=<your temp> LENGTH=100
     Then run a print and check encoder_gain again.

  3. If the gain is STILL low after recalibrating, the problem is mechanical:
     the O-ring is slipping on the filament. Compare the stored deg/mm
     against the wheel geometry --

         deg_per_mm = 360 / (pi * effective_contact_diameter_mm)

     With the stock ~11mm O-ring that is about 10.4 deg/mm. A stored value
     far above that means the wheel is turning less than geometry says it
     should, i.e. it is slipping. Check spring pressure, O-ring wear, and
     that the filament runs straight through the sensor.

===============================================================================
  A NOTE ON serial: auto
===============================================================================

  Auto-detect opens candidate serial ports and writes PING to them. If one of
  those is a Klipper MCU, that write corrupts its protocol stream and takes
  the printer down ("Missed scheduling of next digital out event"), which also
  kills any CAN board bridged through it.

  The module already refuses to probe any port listed in an [mcu] section, but
  a fixed path is safer and costs nothing:

      ls /dev/serial/by-id/
      serial: /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_XX...

  The by-id path is MAC-based and never changes.
